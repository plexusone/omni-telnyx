# Release Notes: v0.6.0

**Release Date:** 2026-10-27

## Highlights

- Audio pipeline mode: the gateway hands raw call audio to your application instead of running STT, LLM, and TTS
- Streaming options for `StartMediaStreaming`, including bidirectional PCMU RTP
- Serialized Media Streaming writes and close-safe session events

## What's New

### Audio Pipeline Mode

Set the gateway's mode to omnivoice-core's `PipelineModeAudio` to run no voice pipeline. The gateway still answers webhooks, starts Media Streaming, and tracks the call, but your application decides when to listen and when to speak. Use it for call recording, live transcription, custom pipelines, or an agent that attends a meeting by phone and speaks only when addressed.

```go
import coregateway "github.com/plexusone/omnivoice-core/gateway"

gw, err := gateway.New(gateway.Config{
    APIKey:      os.Getenv("TELNYX_API_KEY"),
    PhoneNumber: "+14155550199",
    PublicURL:   "https://your-server.com",
    Mode:        coregateway.PipelineModeAudio,
})

sess, err := gw.MakeCallWithOptions(ctx, "+16695550100")
if err != nil {
    return err
}
audio := sess.(coregateway.AudioSession)

go func() {
    for chunk := range audio.ReceiveAudio() { // mu-law (PCMU), 8 kHz, mono
        recorder.Write(chunk)
    }
}()
```

Sessions of an audio-mode gateway implement `coregateway.AudioSession`:

| Method | Behavior |
|--------|----------|
| `AudioFormat()` | Returns mu-law (PCMU), 8 kHz, mono |
| `ReceiveAudio()` | Delivers the remote party's inbound audio; closed when the media stream stops |
| `SendAudio(audio)` | Sends a media frame with the next sequence number |
| `ClearAudio()` | Sends a clear message to drop audio not played yet |

In audio mode the gateway starts Media Streaming with bidirectional PCMU RTP, so audio sent with `SendAudio` plays on the call. `SendAudio` and `ClearAudio` return `ErrAudioNotConnected` before the media stream connects and `ErrSessionClosed` after the call ends. When the media stream stops, the session emits `EventSessionEnded` and closes. Sessions in text and realtime modes do not implement `AudioSession`.

### Streaming Options

`StartMediaStreaming` accepts `StreamingOption` values. `WithBidirectionalPCMU` asks Telnyx to accept mu-law (PCMU) RTP payloads sent back over the stream; without it, Telnyx expects audio sent back to be MP3.

```go
err := call.StartMediaStreaming(ctx, "wss://your-server.com/ws/media-stream",
    callsystem.WithBidirectionalPCMU(),
)
```

## Changed

- `(*callsystem.Call).StartMediaStreaming` now takes variadic `...StreamingOption` after the stream URL. Existing calls such as `call.StartMediaStreaming(ctx, url)` compile unchanged; code that stores the method as a function value or matches it against an interface with the old signature needs updating.
- Outbound media frames share one sequence counter per stream across all senders.

## Bug Fixes

- **Concurrent WebSocket writes**: media, mark, and clear messages could be written to the Media Streaming WebSocket from several goroutines at once, which gorilla/websocket does not allow; writes are now serialized
- **Events after close**: emitting a session event after the session closed could panic with a send on a closed channel; such events are now dropped

## Testing

- Unit tests that drive the media stream handler with simulated Telnyx messages: inbound audio reaches `ReceiveAudio` and the agent's own outbound track does not, `SendAudio` sends sequenced media frames, `ClearAudio` sends a clear message, and stopping the stream ends the session
- Unit tests against a fake Call Control API that audio mode starts streaming with bidirectional PCMU RTP and text mode keeps its previous request
- Tests pass under the race detector

## Migration Guide

### From v0.5.0

Most code needs no changes. Text and realtime modes are unchanged. If you store `StartMediaStreaming` as a function value or declare an interface with its old signature, add the `...callsystem.StreamingOption` parameter. To use audio mode, set `Config.Mode` to `coregateway.PipelineModeAudio`.
